# goSPL参照: Sink容量モデル

## 目的

盆地・池を地形として残したまま、堆積進行に応じて越流が開始される河川ルールを導入する。

## 参照した考え方

本実装はgoSPLのSink処理方針を参照し、次を中核ルールとする。

1. Sinkを検出・ラベリングする。
2. Sinkごとに最小越流地点と容量を計算する。
3. 流入堆積物が容量未満ならSink内保持、容量到達で越流開始。

## 本プロジェクト向けの適用

- くぼ地埋め前処理は行わない。
- 既存の地形・河川状態量と互換を維持し、`river_flux`と`river_next`は継続利用する。
- 越流開始イベント時のみ、対象Sink周辺を局所再計算する。
- 可視化・検証用に`sink_id`、`sink_spill_to`、`sink_capacity_remaining`、`sink_fill_ratio`をWASMフィールドとして公開する。

## 差分と簡略化

- 全球での厳密面積・体積離散化は導入せず、現行の無次元高さ系で容量を近似する。
- まずは決定性と軽量性を優先し、高次の堆積地形表現は段階導入とする。
