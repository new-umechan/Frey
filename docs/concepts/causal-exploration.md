# Causal Exploration Vision

本書は、ユーザーが世界の変化に好奇心を持ち、因果の気配を自分で辿るための体験ビジョンを定義する。
具体的な実装方式、既存モジュール構成、データ構造、画面構成は本書では固定しない。

## Vision

ユーザーは説明文を読むのではなく、世界の中に現れる光、流れ、揺らぎ、数値の変化を手がかりにして、なぜその現象が起きたのかを辿る。

体験の中心は、因果を提示されることではなく、因果に気づくことである。

Frey の因果探索は、学術的な根拠を内部に保持しながら、通常の体験ではそれを前面に出さない。
ユーザーが見るのは論文的な説明ではなく、世界の反応そのものに近い。

## Experience Direction

- 世界を観察して、気になる変化を見つける
- 変化に近づくと、関係する痕跡が静かに立ち上がる
- 痕跡に触れると、影響の向き、強さ、遅れ、不確実性が視覚的に変化する
- 必要な数値は出すが、説明文は最小限にする
- ユーザーは原因を読むのではなく、原因らしき場所へ自然に向かう
- 深く確認したい場合だけ、内部根拠や前提を開ける

この体験は、ゲームのSkyのように、言葉よりも光、距離、反応、余白でユーザーを導く。
ただし、表層を曖昧にしても、内部の因果表現は曖昧にしない。

## Design Principles

- 説明より観察を優先する
- 文章より反応を優先する
- 全体図より局所的な気づきを優先する
- 正解の提示より仮説の発見を優先する
- 常時表示より段階的な開示を優先する
- 演出の美しさより、因果の読み取りやすさを優先する
- 詩的な見え方と、検証可能な内部表現を分離する

## Information Hierarchy

通常時に見せる情報:

- 変化している場所
- 変化の強さ
- 影響の方向
- 影響の相対的な大きさ
- 時間的な遅れ
- 不確実性の気配
- 必要最小限の数値

通常時に抑える情報:

- 長い説明文
- 因果グラフ全体
- 数式
- 文献名
- モデル上の詳細な仮定
- 実装由来の構造

必要時だけ開く情報:

- 根拠の種類
- モデル上の前提
- 近似と省略
- 不確実性の理由
- 参照文献
- 変数名と単位
- 計算条件

## Visual Language

- 異変は、地表や対象の淡い発光、色温度の変化、粒子の乱れとして表す
- 影響経路は、線ではなく流れとして表す
- 影響の強さは、太さ、粒子密度、輝度、反応速度で表す
- 影響の向きは、流れの方向で表す
- 時間差は、伝播速度や遅れて立ち上がる反応で表す
- 不確実性は、輪郭の揺らぎ、途切れ、ぼやけで表す
- 数値は、ユーザーが注目している対象の近くに短く出す
- ラベルは名詞か短い句に留める

## Interaction Model

- 見る: 世界の中から変化や違和感を見つける
- 近づく: 気になる対象へ視点を寄せる
- 触れる: 対象の周囲に因果の痕跡を立ち上げる
- 辿る: 光や流れに沿って、関連する場所や要因へ移動する
- 留める: 気になる痕跡や数値を一時的に固定する
- 比べる: 条件を変えたときの反応の違いを見る
- 深く見る: 必要なときだけ根拠、前提、計算条件を確認する

## Internal Rigor

UI は説明文を減らすが、内部では次の情報を保持する。

- 現象または変数の識別子
- 因果または依存関係の向き
- 影響強度
- 時間遅れ
- 条件依存性
- 不確実性
- 根拠の種類
- 文献、式、仮定、近似
- 未評価の要因
- 表示表現への変換ルール

内部情報は、ユーザーに常時見せるためではなく、表示が何を意味しているかを破綻させないために持つ。
詩的な表現は許容するが、根拠のない断定は許容しない。

## Success Criteria

- ユーザーが説明文を読まなくても、どこに注目すべきか分かる
- ユーザーが自然に痕跡を辿りたくなる
- ユーザーが主要な影響方向を視覚的に把握できる
- 数値が出ても、探索の流れを止めない
- 詳細を開けば、内部根拠と前提を確認できる
- 不確実な関係が、確実な関係のように見えない
- UI 上の美しさが、因果の誤読を生まない

## Failure Criteria

- 説明文を読まないと何をすればよいか分からない
- 数値が表形式に偏り、世界の観察から切り離される
- 因果グラフが主役になり、探索感が失われる
- 演出が強すぎて、影響の強さや不確実性を誤読する
- 内部根拠がなく、見た目だけで因果を示している
- 不明な関係を UI がそれらしく補完してしまう

## Initial Scope

初版では、巨大な因果マップを作らない。
まず、1つの観察フィールドの中で、次の短い探索ループを成立させる。

1. 気になる変化が世界の中に現れる
2. ユーザーが近づく
3. 触れると、最大3つの痕跡が立ち上がる
4. 痕跡ごとに、方向、強さ、不確実性、最小限の数値が見える
5. ユーザーが1つの痕跡を辿る
6. 関連する場所または要因に到達する
7. 必要なら、内部根拠を短く確認できる

この段階では、文章による説明生成、完全な因果グラフ、自由質問、網羅的な文献ビューは扱わない。

## Open Questions

- 数値をどの粒度で出すか
- 数値を常時出す対象と、接近時だけ出す対象をどう分けるか
- ユーザーが触れる対象を、現象、場所、変数のどれとして扱うか
- 不確実性の視覚表現をどこまで直感に寄せるか
- 内部根拠ビューをどの操作で開くか
- 初版で条件比較を入れるか
- 探索対象を時間変化、空間差分、局所異変のどれから始めるか
