# 因果探索モード

## Status

Draft

本書は `docs/concepts/causal-exploration.md` の vision を検証可能な提案に落とす。
ここでは、特定のデモをプロダクト全体の初版スコープとはみなさない。
デモは、見たい体験の一部を切り出した `Demo Slice` として扱う。

## この文書の位置づけ

この文書は、因果探索モードの恒久仕様を決めるためのものではない。
目的は、体験が成立するかを確かめるための実験条件を、実装可能な粒度で定義することである。

ここで固定する内容は、将来の一般仕様を確定するためではなく、今回の検証をぶらさず進めるための一時的な前提である。
実装後の評価結果によって、対象、表現、API、根拠表示は見直してよい。

## 背景

因果探索の vision は、ユーザーが説明文を読むのではなく、世界の中に現れる光、流れ、揺らぎ、数値の変化を手がかりに、原因らしき場所へ自然に向かう体験である。

この体験を実装に落とす前に、まず「その体験が本当に成立するか」を小さく検証する必要がある。
最初から汎用の因果探索 UI、完全な履歴再生、網羅的な因果グラフを作ると、体験の核が検証できないまま実装構造だけが重くなる。

そのため、本 proposal では、初版機能全体ではなく、vision の中核を試すための代表的なデモスライスを定義する。

## 目的

- ユーザーが、説明文ではなく世界の反応を手がかりに、因果の痕跡を辿りたくなるか検証する。
- 数値を出しながらも、表や説明パネルを主役にせず、探索の流れを止めない情報設計を検証する。
- 学術的根拠を内部に保持しつつ、通常時は前面に出さない表示構造を検証する。
- 特定シナリオを、汎用仕様ではなく体験検証用の `Demo Slice` として扱う。

## 提案概要

### 1. Demo Slice とプロダクトスコープを分離する

この proposal で扱うデモは、因果探索モード全体の初版仕様ではない。
あくまでも、次の体験が成立するかを見るための代表スライスである。

1. ユーザーが世界の中で気になる対象を見つける
2. 近づくと、対象が静かに反応する
3. 触れると、最大3つ程度の痕跡が立ち上がる
4. 痕跡は、方向、強さ、不確実性、短い数値を持つ
5. ユーザーが1つの痕跡を辿る
6. 別の対象または深い層へ関心が移る
7. 必要な場合だけ、内部根拠を開ける

デモスライスで実装した対象、数値、視覚表現は、後続の一般化候補であって、ただちに全体仕様にはしない。

### 2. 代表 Demo Slice は「国境 -> 山脈 -> プレート」とする

代表スライスとして、国境を入口にし、山脈を経由して、プレート運動の痕跡へ潜る体験を試す。

このスライスを選ぶ理由:

- 地図上で気づきやすい入口がある
- 国境と山脈の重なりは、説明文なしでも好奇心を起こしやすい
- 山脈からプレートへ辿ることで、表層から深層へ潜る体験を作りやすい
- Frey が扱いたい「地理的制約が人間世界に影響する」感覚を短く見せやすい

ただし、このスライスは「国境は山脈で決まる」という主張ではない。
国境と山脈の関係は、直接因果ではなく、地形制約、可達性、分水界、移動コストとの整合として扱う。

### 3. デモ体験

ユーザーは世界を観察している。
ある国境が、地形の皺に沿うように長く伸びている。

近づくと、国境の一部が静かに明るくなり、短い数値が出る。
触れると、国境の背後に山脈の痕跡が浮かび上がる。

- 国境に沿う細い痕跡: 稜線との整合
- 峠や低地で途切れる痕跡: 通過可能性
- 山体へ沈む深い痕跡: 隆起帯

ユーザーが稜線の痕跡を辿ると、視点は山脈へ移る。
山脈に触れると、さらに深い光が地表下に現れ、プレート境界または圧縮方向へ進む。

プレートまで辿ったとき、表示されるのは長い説明ではない。
収束方向、相対強度、不確実性、必要なら開ける根拠だけである。

### 4. 表示する情報

通常時に表示する情報:

- 気になる国境の位置
- 国境と地形制約の重なり
- 山脈への痕跡
- プレート方向への痕跡
- 影響方向または整合方向
- 相対的な強さ
- 不確実性の気配
- 必要最小限の数値

通常時に抑える情報:

- 長い説明文
- 数式
- 文献名
- 詳細なパラメータ表
- 因果グラフ全体
- モデルの実装構造

必要時だけ開く情報:

- 根拠タイプ
- 使用した変数名と単位
- モデル上の仮定
- 近似
- 不確実性の理由
- 参照文献または参照モデル

### 5. 数値の扱い

数値は出す。
ただし、数値は世界から切り離さない。

この Demo Slice で試す数値:

- 国境と稜線の整合度
- 標高差
- 傾斜または局所起伏
- 峠または通過可能性の相対値
- プレート収束または圧縮の相対値
- 不確実性の段階値

数値表示の原則:

- 対象の近くに短く出す
- 単位または相対基準を明示する
- 常時表示ではなく、接近、注視、固定時に出す
- 桁数を増やして精密に見せすぎない
- 未確定値は推測で補完しない

### 6. 内部厳密性

UI は詩的に見せてもよいが、内部では関係の種類を区別する。

- 国境と山脈の関係: `constraint_alignment`
- 山脈、稜線、分水界などの地形構造: `geomorphic_structure`
- プレート境界、圧縮、隆起などの深部要因: `tectonic_driver`

初版デモで必要な内部データ:

- `phenomenon_id`
- `feature_type`
- `location`
- `geometry`
- `metric`
- `observed_value`
- `baseline`
- `delta`
- `trace_segments`
- `source_feature`
- `target_feature`
- `relation_type`
- `effect_direction`
- `effect_strength`
- `delay`
- `uncertainty`
- `evidence_type`
- `assumptions`
- `approximations`
- `display_mapping`
- `reference_model`
- `reference_notes`

`display_mapping` は、内部値を光、流れ、揺らぎ、数値表示へ変換するための情報である。
UI 層が内部データにない因果を演出で補わないよう、表示に必要な意味はデータ側から渡す。

## スコープ

この proposal で決めること:

- 因果探索モードの次の作業単位を `Demo Slice` として扱う
- 代表スライスを「国境 -> 山脈 -> プレート」とする
- このスライスは初版全体仕様ではなく、vision 検証用であると明示する
- 長い説明文ではなく、痕跡、反応、短い数値で探索させる
- 学術的根拠は内部保持とし、通常時は前面に出さない
- 国境と山脈の関係は、直接因果ではなく地形制約との整合として扱う
- 初回データは生成世界から探索せず、`border_mountain_plate_demo` という静的スライスで返す
- 返す対象は `border_segment`、`ridge_or_mountain_band`、`tectonic_compression_or_plate_boundary` の 3 feature に固定する
- trace は `ridge_alignment`、`passability_break`、`tectonic_driver` の 3 本に固定する
- UI は DTO に含まれない因果を補完しない

この proposal で決めないこと:

- 因果探索モード全体の最終仕様
- 最終的な UI レイアウト
- シェーダや描画方式の詳細
- 具体的なファイル構成
- 永続化形式
- 文献管理の最終仕様
- 国境形成の完全な社会・政治モデル
- すべての現象に共通する一般因果モデル
- どの論文・教科書・経験式を正本の参照にするか

## 成功条件

- ユーザーが説明文なしで、気になる国境に気づける
- ユーザーが国境に近づいたとき、山脈の存在に自然に気づける
- ユーザーが山脈の痕跡を辿り、プレート方向へ進める
- 数値が探索の補助になり、表や文章が主役にならない
- 国境と山脈の関係が、直接因果として誤読されない
- 不確実な関係が、確実な関係のように見えない
- 根拠ビューを開けば、内部の仮定、近似、不確実性を確認できる
- このスライスから、別の Demo Slice に転用できる構造が見える

## 失敗条件

- ユーザーが何を触ればよいか分からない
- 文章を読まないと国境、山脈、プレートのつながりが理解できない
- 数値が多すぎて観察体験を止める
- 光や流れが美しいだけで、方向や強さが読めない
- 国境が山脈だけで決まるように見える
- 根拠の弱い関係が強い関係に見える
- Demo Slice が全体仕様として誤って固定される
- UI 層が内部データにない因果を演出で補ってしまう

## リスクとトレードオフ

- 国境は社会的・政治的な対象なので、地形だけで説明すると誤読を生みやすい。
- 山脈からプレートへ辿る体験は強いが、時間スケールが大きく異なるため、同一の流れとして見せるには慎重な表現が必要である。
- Demo Slice を具体化しすぎると、それがプロダクト全体の仕様に見えてしまう。
- 逆に抽象化しすぎると、体験検証に必要な手触りが失われる。
- 視覚表現を内部値に結びつけるため、初期のデータ設計コストは上がる。

ただし、この制約により次の利点がある。

- Frey らしい地理的因果の入口を短く検証できる
- 最初の実装で巨大な因果グラフを作らずに済む
- ユーザーが自分で見つけた感覚を検証しやすい
- 内部厳密性と詩的な表示を分離しやすい
- Demo Slice 成功後に、別の現象へ横展開できる

## 実施計画

1. Docs-first
    - 本 proposal を追加する
    - 実験条件は本 proposal に集約し、reference 文書は実装に合わせて更新する
    - 実装時にぶれやすい条件は decision にも暫定制約として記録する
2. 情報設計
    - 対象、痕跡、数値、根拠ビューの最小情報を整理する
    - Demo Slice と全体仕様を混同しない用語を固定する
3. データ要件
    - `feature` と `trace_segment` の最小 schema を定義する
    - `constraint_alignment`、`geomorphic_structure`、`tectonic_driver` を区別する
    - `display_mapping`、`reference_model`、`reference_notes` の最小仕様を定義する
4. デモデータ
    - 国境と稜線が強く重なる観察地点を1つ用意する
    - 国境、山脈、プレート境界または圧縮方向を内部データとして接続する
5. 表示プロトタイプ
    - 国境の微発光
    - 触れたときの山脈痕跡
    - 山脈から地表下へ潜るプレート痕跡
    - 近接時の短い数値表示
    - 不確実性の揺らぎ表現
6. 検証
    - ユーザーが説明文なしで国境に気づくか確認する
    - ユーザーが国境から山脈へ自然に関心を移せるか確認する
    - ユーザーが山脈からプレートへ辿れるか確認する
    - 表示が内部データにない因果を示していないか確認する

## 今回の実験固定条件

- デモ ID は `border_mountain_plate_demo` とする
- `world_id` は存在確認にだけ使い、データ本体は固定値で返す
- relation type は `constraint_alignment`、`geomorphic_structure`、`tectonic_driver` の 3 種だけを使う
- evidence には `assumptions`、`approximations`、`uncertainty_reason` を必ず含める
- 詳細な根拠パネルは今回の対象外とし、初回は短い evidence 種別と不確実性理由だけを表示する
- 色、太さ、流速、揺らぎは `display_mapping` からだけ導く

## 未解決事項

- Demo Slice の正式名称
- 国境と稜線の整合度をどう定義するか
- 山脈を稜線、局所起伏、標高、傾斜のどれで代表するか
- 峠や通過可能性を Demo Slice に含めるか
- プレート境界を実境界として見せるか、圧縮方向の痕跡として見せるか
- 時間スケールの差をどのように表現するか
- 根拠ビューをどの操作で開くか
- 痕跡をマウス、タッチ、ゲームパッドでどう辿るか
- 不確実性を揺らぎ、ぼかし、途切れのどれで主に表すか
- 次に検証する Demo Slice を何にするか
