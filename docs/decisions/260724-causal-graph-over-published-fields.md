# Causal graph as a pure function over published fields

## Status

Accepted

## Context

Frey は「架空の惑星の現在を読み、そこから因果を遡る」体験を中核に据える。
その最初の縦スライスとして、セルをクリックすると「なぜ乾燥しているか」を
ノード + 有向辺 + 寄与率の因果グラフで返す `explain_cell` を実装した。

初版の `explain_cell` は `&World`(ライブのシミュレーション状態)を引数に取る。
これはライブ実行(seed=alpha の対話開発)では動くが、公開デモの経路では動かない。
公開デモは precompute サーバーが事前計算した `MaterializedFrame`(フィールド配列 +
メトリクスの束)を配信するだけで、ライブの `World` を保持しないためである。

因果グラフを人に触ってもらう場所は公開デモである。したがって「ライブ経路が本筋で
公開経路は後から辻褄を合わせる」という順序は誤りで、公開を前提とした設計に直す。

## Decision

因果グラフは、**公開されるフィールドの純粋関数**として定義する。ライブ実行時の
内部状態には依存しない。

```text
explain(fields, cell, target) -> graph
```

`fields` はライブ経路では `World` から、公開経路では `MaterializedFrame` から
組み立てる、同じ形のフィールド束(`ExplainInputs`)である。説明ロジックは 1 箇所に
置き、両経路が同じ関数を呼ぶ。

この決定から 3 つの規約が従う。

1. **グラフに出せるノード ⊆ 公開フィールド集合。**
   グラフを深くする(例: 「大気の蒸発要求」を気温・湿度・下降流へ分解する)には、
   その中間量を公開フィールドへ昇格させる必要がある。制約に見えるが、これは正しさの
   担保そのものである。デモを見た人が「このノードの根拠は」と問うたとき、必ず公開
   された場を指させる。データに実在しない値をノードにしない。

2. **エッジ(何が何を駆動するか)はモデルの式に由来する。**
   エッジは `explain` 内に置くが、対応するモデル関数(例:
   `climate/surface.rs` の aridity 定義)への参照をコメントで固定し、モデルを
   変えたらエッジも更新する。将来、各モジュールが自分のエッジと公開出力を宣言する
   形(計算グラフのデータ化)へ発展させる余地は残すが、本決定には含めない。

3. **寄与率は式から厳密配分できるノードだけに付ける。**
   非線形結合で厳密配分できない駆動要因は寄与率を出さず、偏差(z-score)だけを示す。
   `aridity = demand / precipitation` の第一分解のように、式から加法分解できる箇所
   だけが寄与率を持つ。

## Consequences

- `explain_cell` を `&World` 版から `ExplainInputs`(フィールドスライスの束)版へ
  作り直す。ライブ経路の query use case は `World` から、precompute サーバーは
  `MaterializedFrame` から、それぞれ同じ束を組み立てて同じ関数へ渡す。
- 現在の aridity グラフが使う **緯度**と**内陸度(distance_from_ocean)**は
  公開フィールドではない。規約 1 に従い、これらを公開可能なフィールドへ昇格させる。
  どちらも地形由来のほぼ静的な場で、昇格は軽い。
- 説明ロジックが公開データだけに依存するため、ライブと公開でグラフが一致する。
  片方でしか見えない説明は生じない。

## Scope(一人 + AI 開発の前提)

やる:

- `explain` の入力を `&World` から `ExplainInputs` へ変える。
- グラフが使う場(緯度・内陸度)を公開フィールドへ昇格させる。

やらない:

- モジュールがエッジをデータで宣言するフレームワーク化。現規模には重い。式への参照を
  コメントで固定する規律で足りる。

## 実装状況(2026-07-24 時点)

済:

- `explain` を `&World` から `ExplainInputs`(公開フィールドのスライス束)へ分離。
  `explain_from_inputs` が純粋関数、`explain_cell` は `World` から束ねるライブ経路の
  アダプタ(`rust/src/application/world_explain_use_cases.rs`)。
- 緯度・内陸度をライブの公開フィールド API(`get_field`)へ追加。

残:

- precompute フレームが緯度・内陸度を含むよう `default_field_kinds` へ追加する。
- サーバー側の explain エンドポイント。フレームから `ExplainInputs` を組み立て、
  `explain_from_inputs` を呼ぶ。未解決の設計点: フレームは cell_index が一致する
  full-resolution(stride=1)配列を渡す必要がある。biome は公開 i32 から復元する。
- HTTP クライアント(`http-precomputed-engine-client.ts`)の `explain_cell` を実呼び出しへ。
- 上記は `precompute_server.rs` を触るため、別エージェントの作業と競合しないよう分離して実施する。

## Non-goals

- 本決定は、特定ターゲット(aridity)の因果モデルの物理的正しさを主張しない。
  グラフがモデルの式の忠実な投影であること、公開データだけで再現できることのみを保証する。
- 社会系モジュールの因果はまだ対象にしない。ただし本規約(ノード ⊆ 公開集合、
  エッジはモデル由来)は社会系を足すときにも同じく適用する。
