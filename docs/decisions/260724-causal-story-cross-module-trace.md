# Causal story as a cross-module dependency trace

## Status

Draft

閉じる条件: 植生(biome)を起点とする因果ストーリーが 1 本、クリックから
グラフ描画まで通り、reference へ現在仕様を反映したとき Accepted にする。

## Context

Frey の中心体験は「架空の惑星の現在を読み、そこから因果を遡る」ことである。
その入口として、地図上の 1 地点をクリックすると「なぜここはこうなっているのか」を
見せたい。

初版では、クリックした 1 セルの乾燥度(aridity)を蒸発要求と降水へ分解する
`explain_cell` を実装したが、これは 1 つの量を割り算で分けるだけで、分野をまたいで
原因が連鎖する「物語」にはなっていなかった。三本柱の「おもしろさ = 情報と情報が
つながる」を満たさないため取り消した(commit revert 済み)。

本決定では、体験を**分野をまたいだ原因の連鎖**として作り直す。

## 何を作るか(平易な説明)

地図の 1 地点をクリックすると、その地点が「なぜ今の姿なのか」を、原因をさかのぼる
小さな図で見せる。図はノード(丸)と矢印でできていて、矢印は「これがこれを決めている」
という因果を表す。ノードは地形・気候・植生といった別々の分野にまたがる。

例: 砂漠の地点をクリックしたとき

```text
砂漠 (植生)
  ↑
降水量が少ない (気候)
  ↑
気温 (気候) ← 緯度
  ↑
標高が高い (地形)
  ↑
プレートの動き (地形)
```

矢印とノードの値(降水量が少ない、など)で因果は伝わるので、「境目を下回ったため」
のような説明文はエッジに載せない。森や湿地の地点なら、決め手になる条件が変わり、
図の形も変わる。「その地点がなぜその姿なのか」に応じて、毎回違う物語が出る。

## Decision

1. **因果グラフは、公開されているフィールドの純粋関数として組み立てる。**
   ライブ実行時の内部状態には依存しない。ライブ経路も公開デモ経路も、同じフィールドの
   束から同じ関数で組む。(初版 decision の原則を引き継ぐ)

2. **グラフは、モデルが実際に持つモジュール間の依存を辿って作る。**
   エッジ(矢印)は物語のために創作せず、コードの依存関係に一致させる。各エッジには
   対応するモデル関数への参照をコメントで残し、モデルを変えたらエッジも直す。

   最初のストーリー(植生 biome)の依存は実コードで次の通り:
   - 植生の種類は `標高・気温・降水量・河川流量・樹冠` の閾値カスケードで決まる
     (`sim/ecology/mod.rs` の `classify_biome`)。
   - 気温は `緯度で決まる基準温度 − 標高 × 逓減率`(`sim/climate/surface.rs`)。
   - 標高は地形(プレート)由来。

3. **決め手になった要因を、テキストではなく構造で示す。**
   `classify_biome` は閾値カスケードなので、その地点の種類を決めた分岐が 1 つある
   (砂漠なら降水、ツンドラなら気温)。決め手の要因ノード/エッジは視覚的に強調する
   (太さ・色など)が、「境目を下回ったため」のような説明文は載せない。矢印とノードの
   値で因果は伝わる。冗長な注釈は図の可読性を下げる。

## Scope(一人 + AI 開発の前提)

やる:

- 同じ地点の中で分野を縦断する連鎖(地形 → 気候 → 植生)。空間移動を伴わない。
- 起点は植生(biome)。「なぜ砂漠/森/ツンドラ/高山か」を辿れるようにする。

やらない(将来の拡張として残す):

- 場所をまたぐ因果(例: 「降水が少ないのは風上の山が雨を落としたから」= 雨陰、
  「ここに川があるのは上流の集水域が集まるから」)。風の場や河川ネットワークを
  空間的に辿る必要があり、次段で扱う。
- 地物の切り出しと命名(「A 山脈」「B 河川」のような固有名を持つ実体)。
- 社会系モジュール(人口・集落・国家・国境)。未実装のため連鎖の対象にしない。

## Consequences

- 取り消した初版の配管(wasm バインディング、TS 配線、ノード + エッジ + 要約の
  応答形)は、応答形が同じなので再実装して流用する。作り直すのはグラフ構築ロジック
  (単一量の分解 → モジュール横断の依存トレース)。
- 決め手の条件を再現するため、`classify_biome` の閾値をどこかで参照できるようにする
  必要がある。値の二重定義でモデルと食い違わないよう、ecology 側の定数を共有する。
- Figma の因果パネルは変更不要。ノード + 矢印の描画はそのまま使え、流し込むデータが
  物語になるだけ。

## Non-goals

- 本決定は、各モジュールの物理的正しさを主張しない。グラフがモデルの依存関係の忠実な
  投影であること、公開データだけで再現できることのみを保証する。
